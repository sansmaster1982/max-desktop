# Building the public Windows variant

The exported source is intentionally different from the development checkout:
the copied call SDK, original MAX icons/wallpaper art and notification MP3 are
not distributed. The replacement SVG masks and WAV are generated by
`prepare_public.py`. Do not run that development export helper in a downloaded
release: the release source is already curated.

Use Windows x64 and CPython **3.11.9**. From a clean source checkout with these
tools under `tools/`:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r tools/requirements-build.lock
.venv\Scripts\python tools/run_public_tests.py --source . --out artifacts/test01
.venv\Scripts\python tools/build_public.py --source . --out artifacts/build01
```

Each output directory must be new. Logs and source hash manifests are retained.
The build produces `dist/MAXIM/MAXIM.exe` and an onedir ZIP. Keep the `_internal`
directory and all DLLs with the executable; copying the EXE alone will not work.
The EXE is unsigned; no Authenticode/SmartScreen reputation is claimed.
The portable alpha also excludes QtWebEngine/WebChannel and Chromium. Mini-app
actions stop before any service request and display an unavailable notice in the
frozen executable. Their development source remains available separately.

The smoke test uses `--selftest`, a mandatory empty data directory and a Python
audit hook blocking sockets/account paths. It constructs the login window and
QtMultimedia; it does not authenticate, connect, send a message or demonstrate
that every native Qt network path is blocked. Never run smoke tests on a real
profile. Real session compatibility remains a separate opt-in test.

Exact package versions are pinned. This is a repeatable build recipe, **not a
claim of bit-identical reproduction**: wheel downloads are not hash-locked yet,
and Python/Qt/compiler inputs must also be recorded. To strengthen provenance,
download wheels into a reviewed wheelhouse, record SHA256, and use
`pip --no-index --require-hashes` with that platform-specific lock.

Before publishing a ZIP, review `third_party_licenses/`, the root third-party
notice and Qt/Chromium/FFmpeg source/notice obligations for the exact collected
DLLs. Existing license files alone do not establish complete compliance.

Recommended Windows CI: `windows-2022`, Python3.11.9, install the lock, run the
same offline test helper, build only on success, retain test/build receipts and
ZIP as workflow artifacts. Run on `pull_request` and push to the actual default
branch. Publishing a release should be a separate explicit workflow/environment
gate; do not upload to a store or GitHub Release merely because a push occurred.
Pin third-party Actions by reviewed commit SHA. No signing credentials belong
in the source tree or artifact; configured signing must use protected CI secrets.
